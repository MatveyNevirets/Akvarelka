# Акварелька · Казань

Готовый статический сайт без зависимостей. Запуск: `npm run dev`, адрес http://127.0.0.1:5187. Проверка JavaScript: `npm run check`. Для обычного хостинга загрузите содержимое `dist/`.

## Заявки

Форма проверяет имя, возраст, направление и полный телефон, затем отправляет JSON через `dist/lead-api.mjs`. Перехода в WhatsApp, подготовки текста и второго действия пользователя в форме нет. Кнопка блокируется на время запроса. Success показывается только после HTTP 2xx и JSON-ответа `{ "success": true }`; сетевые ошибки, неуспешный HTTP, неверный JSON и неподтверждённый ответ показывают error-state и логируются в консоль без технических деталей в интерфейсе.

Реальный backend пока не подключён. При пустом `<meta name="lead-endpoint" content="">` работает локальная асинхронная заглушка: она подтверждает полностью заполненную валидную форму и показывает success-state, но никуда не сохраняет заявку. Для подключения backend укажите его путь, например `<meta name="lead-endpoint" content="/api/leads">`, в `dist/index.html`. Запрос: `POST`, `Content-Type: application/json`, поля `parentName`, `childAge`, `phone`, `direction`, `directionLabel`, `context`, `source`. Backend должен вернуть JSON `{ "success": true }` только после фактического сохранения или передачи заявки. Секреты, rate limiting и обработка персональных данных должны находиться на сервере.

Маска в `dist/phone-mask.mjs` показывает номер как `+7 (927) 123-45-67`, поддерживает вставку с 8/7/+7, автозаполнение, выделение и редактирование середины номера. Скрытое поле `phone` содержит нормализованный номер `+79271234567`. Видимое поле имеет `autocomplete="tel"` и телефонную клавиатуру.

Направления выбираются нативными радиокнопками, оформленными как переключатели в текущей палитре. Поддерживается клавиатура. Тематические CTA выбирают своё направление, общие — консультацию; после любого CTA выбор можно изменить вручную. Подсказки об ошибках появляются после выхода из поля или попытки отправить заявку. После подтверждённого успеха поля и ошибки сбрасываются, а success-card остаётся видимой.

## Микроанимации

`dist/motion.mjs` добавляет однократное появление при прокрутке и stagger до 120 мс, мягкое появление фото, открытие/закрытие FAQ с поддержкой повторных кликов, параллакс стикера до 6 px только на desktop с точным указателем. CSS дополняет hover/focus кнопок, карточек и направлений. Постоянных циклических анимаций нет. На touch упрощены эффекты, на мобильном убраны задержки и параллакс. `prefers-reduced-motion` поддерживается при загрузке и изменении настройки. Без IntersectionObserver контент остаётся видимым. Библиотек анимации и новых runtime-зависимостей нет.

## Проверка

`npm run build` выполняет синтаксическую проверку и 27 DOM/API-тестов: маска, валидация, CTA, ручная смена направления, JSON payload, защита от повторной отправки, loading/success/error, меню, reveal, FAQ и reduced-motion. Для тестов используется dev-зависимость `happy-dom`. Сам сайт статический и не требует runtime-пакетов.

`npm run audit:responsive` использует установленный Chrome через dev-only `playwright-core`. Проверены 320, 360, 375, 390, 393, 412, 430, 768, 820, 1024, 1280, 1366, 1440, 1600 и 1920 px, отсутствие горизонтального overflow и clipping, touch-targets и консоль. Отдельно проверены меню, ошибки полей, loading, success и error. Скриншоты сохраняются в игнорируемую папку `qa-screenshots/`. Safari/WebKit на Windows недоступен; safe-area, `viewport-fit=cover`, `dvh`, отсутствие `100vh`, input zoom и скрытие нижнего CTA при фокусе формы проверены по реализации и в mobile Chrome emulation.
